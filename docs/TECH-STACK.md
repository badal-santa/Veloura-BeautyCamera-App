# Veloura — Tech stack and packages

What Veloura is built with, and why each package is there. For what the app does, see [FEATURES.md](./FEATURES.md).

## Platform

| | |
|---|---|
| Framework | React Native 0.86 via **Expo SDK 57** (development builds, not Expo Go) |
| Language | TypeScript (strict) |
| Styling | Tailwind CSS through NativeWind — styles are `className` strings |
| Native code | Generated by `expo prebuild` from `app.json` + config plugins. The `android/` folder is never edited by hand. |
| App ID | `com.veloura.app` (see *App identity and signing*) |
| Package manager | npm (`package-lock.json`). Add packages with `npx expo install` so versions match the SDK. |

## Native Android code (`modules/veloura-launcher`)

A local Expo module written in Kotlin. Despite the name it holds all Android-only features, because none of them have a suitable Expo package.

| Capability | Built on | Used by |
|---|---|---|
| List installed apps with icons, launch, app info, uninstall, package-change events | Android PackageManager, `<queries>` for launcher apps (avoids the restricted "all packages" permission) | Veloura Home |
| Turn Home mode on/off, ask to be the default Home app, Home-button detection, expand notifications | Component enable/disable, RoleManager (`ROLE_HOME`) | Veloura Home, first-run prompt |
| Video info, thumbnails, lossless trim, mute | MediaMetadataRetriever, MediaExtractor + MediaMuxer | Video Studio |
| Face detection with contours | **Google ML Kit Face Detection** `com.google.mlkit:face-detection:16.1.7` (model bundled, offline) | Skin-smart beauty, makeup |
| Person cut-out | **Google ML Kit Selfie Segmentation** `com.google.mlkit:segmentation-selfie:16.0.0-beta6` (bundled, offline), plus a guided filter and colour decontamination for clean edges | Remove BG |

The two ML Kit models add roughly 10–15 MB to the app.

## Deliberately not used

- **No ads, analytics or crash-reporting SDKs** (unlike the reference app, which ships AdMob and Firebase Analytics). The privacy text in the app depends on this.
- **No FFmpeg** — trimming uses Android's built-in media APIs, keeping the app far smaller.
- **No backend or account system.**

## Commands

```bash
npx expo start                    # dev server
npx expo run:android              # build and install a development build
npx tsc --noEmit && npx expo lint # type check + lint (run before every change is done)
cd android && ./gradlew bundleRelease assembleRelease   # signed .aab (Play) + .apk
```

Building needs the JDK bundled with Android Studio:
`export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## App identity and signing

| | |
|---|---|
| Android package / iOS bundle ID | `com.veloura.app` — permanent once published |
| Version | `1.0.0`, versionCode `1` (bump `android.versionCode` in `app.json` for every Play upload) |
| Upload key | `~/.veloura-keys/veloura-upload.jks`, alias `veloura-upload`, RSA 4096, valid until 2054 |
| Upload key SHA-256 | `E7:B7:29:90:95:71:09:91:0A:D9:AB:CE:A4:8A:80:19:EF:99:96:A5:A6:8C:E8:19:6E:E1:79:E5:64:6C:B0:22` |

The keystore and its password are **never in the repo**. Gradle reads them from `~/.gradle/gradle.properties`:

```properties
VELOURA_UPLOAD_STORE_FILE=/Users/<you>/.veloura-keys/veloura-upload.jks
VELOURA_UPLOAD_KEY_ALIAS=veloura-upload
VELOURA_UPLOAD_STORE_PASSWORD=…
VELOURA_UPLOAD_KEY_PASSWORD=…
```

Back up `~/.veloura-keys/` (keystore + `README-BACKUP-THIS.txt` with the password) somewhere safe and offline. Enrol in **Play App Signing** on first upload: Google then holds the real app-signing key, and a lost upload key can be reset through Play support.

## Known gaps before Play Store release

- A privacy policy URL.
- No crash reporting (decided against for now — keeps "nothing leaves your phone" true).
